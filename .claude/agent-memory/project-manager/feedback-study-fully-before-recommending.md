When Bro asks to evaluate/learn an intel source, READ THE ACTUAL CORE MATERIAL before giving any skip/adopt verdict. Surface-level crawl + premature "not worth it" = rejected.

**Why:** 2026-06-09, hesz_journal Telegram eval. Sirius crawled 803 posts but the actual tutorial core was locked in HTML attachments (`lp-screening-guide.html`) that web-preview couldn't render — never read. Polaris still recommended "skip, beginner-level." Bro corrected: "pelajari dulu semuanya baru kasih rekomendasi, gimana sih." Verdict on un-read core = not acceptable. A guess dressed as a conclusion.

**How to apply:**
- Before recommending skip/adopt on any source: confirm the LOAD-BEARING content was actually retrieved + read, not just the easy-to-fetch surface.
- If core material is behind a blocker (attachment, login, paywall, classifier-blocked VPS cmd) → either find another path to get it (public X mirror, WebFetch linked content, prep a one-liner for Bro to run) OR explicitly state "verdict pending — core unread" instead of concluding.
- Honest "I haven't read X yet, getting it now" > confident verdict on partial data. This complements [[feedback-no-fabrication]] (don't invent) — also don't conclude on gaps.
- Applies to intel sources, tutorials, competitor strategy, any "evaluate this" ask.
- Tension with lean/[[feedback-lean-no-menus]]: lean = decide fast, but NOT decide on unread data. Thoroughness on the INPUT, decisiveness on the VERDICT once input is complete.
